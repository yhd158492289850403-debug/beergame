# 啤酒游戏 · 单人 / 联机

一个无需注册的啤酒游戏（供应链 / 牛鞭效应教学模拟），支持离线单人、最多四人房间联机和本地合成背景音乐。
单人模式中其余角色由 AI 控制；联机模式中朋友各自负责一个角色，空位由 AI 补齐。

## 怎么玩

**Windows 便携版：双击 `dist/BeerGame.exe`。** 内置游戏和 Node 联机服务，无需安装 Node。顶部可复制局域网地址，也可一键开启互联网临时地址，再将地址与房间码分享给朋友。正常关闭后结束相关进程并清理本次临时目录。兼容 Windows 10/11 x64，使用系统已有的 WebView2。占用与异常退出的清理边界见 `desktop/README.md`。

第一次玩可以点击页面顶部「新手教程 · 2 分钟」。五步介绍供应链、库存与缺货、运输延迟，并提供独立练习订单及结算。练习复用游戏逻辑，不会改动正式对局或开局设置；可随时关闭、按 Esc 退出或重新观看。联机期间打开教程不会暂停房间。

教程浏览器验证：`node tests/check-tutorial.js`。

**最简单的方式：直接双击 `index.html`**（或在浏览器里打开这个文件）。
不需要装任何东西、不需要起服务器、不需要联网。

已在 `file://` 协议下验证：可完整玩完一局，且**零远程资源请求**（完全离线）。

## 开局设置

| 设置项 | 选项 | 说明 |
|---|---|---|
| 玩家角色 | 零售商 / 批发商 / 分销商 / 工厂 | 你亲自下单的那个角色，其余由机器人控制 |
| 机器人智能度 | 简单 / 普通 / 困难 | 三档在预测、库存调整速度与备货倾向上有区别（见下） |
| 游戏周期数 | 18 / 36 / 54 | 一局的总周期（周）数 |
| 初始库存 | 0–30 滑块 | 所有角色相同的起始库存 |
| 初始在途订单 | 0–20 滑块 | 每段在途的起始量（在途分近/远两段） |
| 需求模式 | 稳定 / 阶梯式增长 / 随机波动 | 可进一步调整起始需求、增量、变化周期、上下限、波动幅度 |
| 显示其他节点库存情况 | 开 / 关（默认开） | 关闭后其他节点的库存、缺货、在途显示为“—”，更接近真实啤酒游戏的信息隔离体验 |
| 进阶选项 | 订单额外延迟一周期 | 开启后订单要两周期才到达上游，难度更高 |
| 随机种子 | 整数 | **相同种子会得到完全相同的对局**，便于复现与教学对比 |

### “显示其他节点库存情况”关掉后会发生什么

| 信息 | 关闭后 |
|---|---|
| 自己的库存 / 缺货 / 在途（含看板与顶部数据条） | 始终可见 |
| 其他节点的库存 / 缺货 / 在途（看板节点 + 信息表三列） | 显示为 `—`，库存条也不再绘制 |
| 其他节点的累计成本 | 仍然可见（成本不属于“库存情况”） |
| 各节点的本周期需求 | 仍然可见（订单相关信息，不属于库存） |
| 运输动画中的“N 件”标签 | 隐藏，避免通过动画泄漏上游发货量 |
| 看板下方的提示 | 显示一行说明，告知当前处于隐藏模式 |

这是一个**纯界面可见性开关**：它不参与任何计算，开启与关闭时对局结果完全一致（有断言保证）。

## 游戏规则

- 供应链：**顾客 → 零售商 → 批发商 → 分销商 → 工厂**（工厂自行生产）。
- **订单上行**：`t` 期下的订单在 `t+1` 期到达上游（开启"订单额外延迟"后为 `t+2`，延迟 2 期）。
- **货物下行**：发货经两段在途，**2 期后**到达下游（`t` 期发出 → `t+1` 进入近段 → `t+2` 入库）。
- **上游按订单发货**：上游在 `t` 期发出的是下游**按提前期到达的订单量**加自身缺货；
  即 `t` 期发的是下游 `t-1` 期下的单。这条因果链是牛鞭效应的来源，也是玩家订单能影响上游的唯一途径。
- 每期每个节点的成本 = `0.5 × 期末库存 + 1.0 × 期末缺货`。
- 顾客需求只直接作用于零售商；零售商的需求变化会沿链路被逐级放大，这就是**牛鞭效应**。
- 一局结束后给出：你的成本、供应链总成本、牛鞭效应比值、各角色成本分解。

## 机器人智能度（三档的真实区别）

所有档位都记录运输在途和已下单未发货的数量，只使用本节点已到达的需求。没有未来需求读取、强制最低补货或额外重复计算缺货。

| 档位 | 决策方式 |
|---|---|
| 简单 | 较快修正库存，额外保留两周需求作为安全库存，波动时容易过量备货 |
| 普通 | 平滑预测需求，按补货提前期设定目标，逐步修正库存位置 |
| 困难 | 较快识别需求变化，小步修正库存，按波动及持有/缺货成本比例设定安全库存 |

库存位置 = 库存 − 缺货 + 运输在途 + 已订未发。目标覆盖当前周需求、订单传递和两周运输；工厂仅考虑两周生产。订单范围统一为 0–200 箱。

36 个标准对局（3 种需求 × 12 种子）的回归要求：困难档成本低于普通档的比例至少 90%，困难档订单波动比简单档低至少 30%。这些是测试场景的结果，任意玩家行为、成本配置与短局并不保证严格排名。

## 界面结构

- **供应链全景图**：SVG 绘制的可视化布局，展示每个节点的库存条、缺货条、在途管道读数与顾客需求。
- **动画**：订单卡沿链路上行、卡车沿链路下行、库存条按周期过渡、收货节点闪光、缺货节点抖动、成本折线增量绘制。
- **订货参考**：显示建议量、需求预测、库存位置与已订未发数量；点击填入，不会自动确认订单。建议只使用本角色已知信息，不保证最优。
- **控制区**：本周面对的需求、你的库存/在途/缺货、订货量输入（含快捷选项）。
- **信息面板**：各节点实时状态表 + 累计成本趋势图。
- **结算界面**：关键指标卡 + 各角色成本分解表 + 缺货周数提示，可导出带中文编码的逐周 CSV。
- **窄屏顺序**：先显示下单操作，再显示供应链全景和状态表，减少每周操作所需滚动。
- **进阶选项**：默认折叠；对局中可返回设置。

## 视觉设计（简约中性风格）

设计依据 `minimalist-ui` 协议（暖中性单色 + 深灰操作色和淡绿选中态，拒绝渐变与重装饰），并用 `check-design.js` 固化为可复核的自动断言。

| 维度 | 做法 |
|---|---|
| 配色 | 暖中性画布 `#fafaf9` + 纯白卡片；文字用统一暖灰阶（`#2f3437` / `#6b6f72` / `#747570`），避免冷/暖灰混用 |
| 强调色 | 深灰 `#303732` 用于主操作，淡绿 `#edf3ec` 用于选中态与我的角色 |
| 状态色 | 浅底深字的语义色（缺货红 / 完成黄 / 收货绿），只出现在状态标签与告警数字上 |
| 表面 | 卡片仅 `1px solid #eaeaea` 描边，**无渐变、无玻璃模糊、无 box-shadow** |
| 圆角 | 容器 12px、控件 8px、按钮 6px；不使用 pill |
| 字体 | 系统几何无衬线栈（含中文回退）；所有数值用 `tabular-nums` 等宽数字便于纵向比对 |
| 图标 | 内联 SVG 线性图标；无 emoji |
| 留白 | 区块间距 24–32px、卡片内边距 24–40px，靠分隔线与字号层级建立秩序 |
| 动效 | 只有极轻的淡入位移（380ms，仅 `transform`/`opacity`），不做循环装饰动画；尊重系统"减少动效"偏好 |

窄屏下全景图改为**横向滚动**，而不是把整张图缩小到文字只剩几像素：实测图内文字渲染字号 9.3px，保持可读。

```
beergame-solo/
├── index.html                  入口（直接打开即可）
├── styles.css                  全部样式（含响应式与动效偏好适配）
├── src/
│   ├── game-logic.js           纯逻辑核心：状态、单周期循环、机器人 AI、需求模式
│   └── game.js                 UI 绑定：设置界面、全景图、动画引擎、结算

```

游戏运行**零依赖**：没有第三方 CSS/JS，也不需要构建步骤。

## 技术说明

- **不用 ES module**：`file://` 下 `<script type="module">` 会被 CORS 拦截，
  因此采用传统 `<script>` 标签按序加载，逻辑通过 `globalThis.BeerGame` 暴露。
- **逻辑与界面完全解耦**：`src/game-logic.js` 是纯函数（无 DOM、无定时器、无网络），
  因此可以在 Node 里直接 `require` 并做完整的单元测试。
- **可复现**：随机数来自种子化 PRNG（mulberry32），同种子必然产生同一局。
- **可访问性**：统一的 `:focus-visible` 焦点环、语义化标签与 `aria-label`、数值与标题使用足够对比度的灰阶。

## 联机与背景音乐

在本目录打开终端，运行 `node server.js`（Node.js 22 或更新版本，无需 npm 安装），然后访问 http://localhost:3000。

同一 Wi-Fi / 局域网的朋友打开 `http://房主电脑的局域网IP:3000`，选择不同角色，输入房间码加入。房主选择开局参数后创建房间，等大家加入再点击「开始联机对局」。最多四人，空位由 AI 控制；每周所有玩家提交订单后服务器统一结算。已提交订单不可修改。

刷新同一标签页会恢复席位；主动离开或断线超过 90 秒由 AI 接手，房主离开后房主身份移交给剩余玩家。开始后不再接受新玩家。服务器重启会清空所有房间。跨互联网游玩需要把这个 Node 服务部署到大家可访问的服务器；本项目尚未部署公网服务。Windows 如提示防火墙权限，局域网联机需允许该服务在私人网络被访问。

「隐藏其他节点库存」仍与原版一样是界面开关，并非防作弊隔离；服务会向房间成员同步完整对局状态，适合朋友协作教学。

页面顶部的背景音乐默认关闭，点击开启。音乐由浏览器本地合成，无需下载音频，支持音量调整，切到后台自动暂停。直接双击 index.html 时，单人模式和音乐仍完全离线可用。

新增验证：`node tests/online.test.js`（服务端联机流程），`node tests/check-online.js`（浏览器联机、恢复和音乐开关）。
